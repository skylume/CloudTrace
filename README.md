# ☁️ CloudTrace 云迹

[![Go 1.25+](https://img.shields.io/badge/Go-1.25%2B-00ADD8.svg)](https://go.dev/)
[![License](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

**CloudTrace 云迹** 是一款带有现代化图形界面的 Cloudflare IP 扫描与测速工具，  
同时提供 **桌面版（原生窗口）** 与 **纯 HTTP 管理面板** 两种形态：两者共用同一份
handler 与同一份数据，桌面版开着的时候浏览器也能访问同一个面板。  
从延迟探测、可用性校验到真实下载测速与综合评分，全部由本项目独立实现。

[👉 点此前往下载页面](https://github.com/skylume/CloudTrace/releases/latest)

## ✨ 功能特性

### 🚀 智能高效扫描
- **全异步高并发**：Go 协程池实现，并发数由你定（默认 200；上限跟着「网络 → 全局并发上限」走，默认 2000、可调到 10000），极速完成海量 IP 筛选。
- **智能随机采样**：从 Cloudflare 官方 CIDR 段智能拆分 /24 子网并随机生成 IP，自动去重并支持采样上限，避免无意义遍历。
- **双延迟模式**：TCPing（TCP 握手延迟，基准）与 HTTPing（TTFB，阈值自动 ×1.3/×4.0 换算），应对不同网络干扰环境。
- **精准 TCP 延迟**：多次探测并发发起取最小值，数据更真实可靠。
- **四块来源自由组合**：官方网段、远端地址（多组，各自启停 + 重试/间隔/超时）、自定义文本、本地文件——拖一个 `txt/csv/json` 进来即可，四块可同时生效。
- **一个框吃所有格式**：自定义文本里 CIDR、单个 IP、`IP:端口`、IP 段（`a-b`）、域名、带 `http(s)://` 前缀的链接、`#` 注释全部自动识别，输入时实时显示「识别到 N 个网段 · N 个单点 · N 个域名」。
- **端口前置过滤**：在 TCP 测试之前先按端口剔除候选，省下并发预算。

### ⚡ 专业下载测速
- **内置真实测速**：通过 `speed.cloudflare.com` 下载大文件实测带宽（校验状态码、响应头后计时、chunked 解码，杜绝假高速）。
- **自动测速源选择**：`auto` 模式会先探测出口 ISP，识别到中国移动宽带时自动切换移动友好测速源；界面会明说「为什么用了这个源」。
- **限速熔断与并发控制**：连续命中 HTTP 429 会自动熔断本批测速，并给出可操作的建议（一键把并发降下来）；支持 1~16 并发与「提前收敛」（收够 N 个合格结果即停止）。
- **综合评分排名**：`score = 速度权重 × MB/s ÷ (1 + 延迟权重 × 延迟秒)`，权重可在设置中调整，比单一速度更科学。
- **可用性验证**：测速前校验节点 `Server: cloudflare`，自动淘汰被劫持 / 非 CF 节点。
- **勾选即测**：在结果表里勾选若干节点（表头可一键全选），点「测速选中 N」就开始；想只测某个地区，用扫描页的地区分布芯片先把表筛出来再全选。
- **测速地址预设 + 自定义**：内置「自动选择 / 官方源 / 移动友好 / 移动专属」四个预设一键切换，也可选「自定义…」手填任意 URL（`http://` / `https://` 决定是否走 TLS）。

### 🎯 精准节点识别
- **双栈全面覆盖**：全面支持 Cloudflare 官方 IPv4 与 IPv6 地址段扫描。
- **IATA 深度解析**：自动获取节点的 IATA 机场代码，并内置 90+ Cloudflare 常见代码的中文汉化映射（如 NRT->东京, HKG->香港）。
- **双重识别机制**：优先解析 `/cdn-cgi/trace`，若失败自动回退解析 HTTP 响应头中的 `CF-RAY` 字段，确保识别成功率。
- **ASN 归属地库**：内置 iptoasn 数据源（免账号、体积小），也支持 GeoLite2；可定时自动更新，更新时写回正在使用的那个文件。

### 🎨 现代化交互体验
- **四页导航 + 双视图**：左侧「扫描 / 结果 / 历史 / 设置」；「测速」是结果页里的一个视图，同一批数据在两个关注点之间切换。
- **渐进式披露**：首屏只留「档位 + 开始扫描」——第一次进来的用户不必先读懂六个面板才敢点按钮；「详细设置」展开后才露出数据源、参数明细、筛选漏斗与运行日志。
- **档位一键套用**：内置「快速 / 标准 / 精细」三档，参数手调后档位会显示「已偏离『标准』」，可随时「另存为我的档位」；自定义档位支持导入导出、置顶、设为启动档位。
- **智能推荐**：按当前网络环境探测一次并给出一组参数——它是自动自适应的手动对应物，点了才生效，改完可以还原。
- **指标卡**：结果视图看延迟（可用 IP / 覆盖地区 / 最低延迟 / 平均延迟），测速视图看速度（最快下载 / 平均下载 / 测速合格 / 总数），随筛选实时联动。
- **结果表**：列预设（精简 / 标准 / 完整）、分组（不分组 / 按数据中心 / 按地区 / 按 ASN）、关键词搜索、分页；延迟与速度带颜色条，当前排序维度的前 3 名标「推荐」；行可展开看全部字段与节点明细，双击单元格快速复制。
- **过程面板**：扫描页右侧实时显示阶段名、进度与预计剩余，配上「生成候选 → 延迟达标 → 地区解析 → 最终可用」的筛选漏斗，一眼看出结果是在哪一步被筛掉的；漏斗下面的地区分布芯片点一下就能把结果表按地区筛出来。
- **命令面板与快捷键**：`Ctrl+K` 唤起命令面板；`Ctrl+Enter` 开始扫描、`Esc` 停止、`Ctrl+F` 聚焦结果搜索、`Ctrl+Shift+A` 切换披露程度、`Ctrl+C` 复制选中节点。
- **轻提示与空状态**：操作反馈走右下角 Toast；无数据时给图标 + 文案 + 快捷入口，而不是一张空白表格。
- **移动端适配**：窄屏下换成底部标签栏与卡片列表，左滑即复制。
- **系统托盘**：关闭窗口默认收进托盘（可关掉），托盘图标悬停显示任务进度，菜单可显示主窗口、停止当前任务、退出。

### 🌐 双形态发行
- **桌面版**：原生窗口，同时在本机监听（默认 `127.0.0.1:17443`），浏览器打开就是同一个面板——不是两套实现，是同一个 handler 的两个出口。
- **面板版**：纯 HTTP 服务（不带 GUI 依赖，体积更小），一个 exe 启动，浏览器管理扫描/测速/历史/设置。
- **WebSocket 实时推送**：进度、日志、结果一路推过来；断线自动重连，支持 Token 鉴权与局域网访问开关。
- **双 UI 同步**：桌面窗口与浏览器面板共享同一任务状态，可同时打开、互相实时可见。

### 💾 完善的数据管理
- **自动历史存档**：扫描与测速结果自动带时间戳保存，并实时更新 `latest` 副本，支持一键加载历史记录，无需重复扫描。
- **历史即资产**：列表走索引（不打开任何记录文件）、条目可收藏打标签、两份之间能对比出延迟与节点变化、加载时会提示「这份是用别的参数跑的」。
- **多格式导出**：支持将结果一键导出为 CSV / JSON / TXT 三种格式，可勾选导出字段、只导出合格结果；TXT 每行输出 `ip:port`，可直接粘贴进代理客户端。
- **原子写入**：设置与历史文件均采用「临时文件 + fsync + 原子替换」写入，进程中途崩溃也不会留下半截 JSON。
- **单实例保护**：同一时间只允许运行一个实例，避免桌面版与面板版抢占端口与历史目录（`CLOUDTRACE_ALLOW_MULTI=1` 可强制多开）。
- **旧版数据迁移**：检测到旧版数据时只弹一条横幅，点「导入」才动数据——复制而非移动，先备份再写，重复执行是覆盖而不是再导入一份。

### ⚒️ 极致系统兼容
- **Win7 深度适配**：单独一条构建线（社区维护的 Go 分支工具链），并为 Win7 桌面版附带固定版本的 WebView2 运行时——系统自带的那个版本在 Win7 上装不上。

## 🚄 安装与运行

### 环境要求

- **运行**：Windows 7 SP1 及以上。
- **从源码构建**：Go 1.25+；只在需要重新构建前端时才要 Node.js 18+。
  桌面版**不需要** wails CLI，也**不需要** C 编译器——直接 `go build` 即可。

### 使用预编译版本

从 [Releases](https://github.com/skylume/CloudTrace/releases/latest) 页面下载对应压缩包：

| 包 | 适用 |
| :--- | :--- |
| `cloudtrace-panel-<版本>-win-x64.zip` | Windows 10/11 面板版：双击后浏览器访问 |
| `cloudtrace-desktop-<版本>-win-x64.zip` | Windows 10/11 桌面版：原生窗口 |
| `cloudtrace-panel-<版本>-win7-x64.zip` | Windows 7 面板版 |
| `cloudtrace-desktop-<版本>-win7-x64-lite.zip` | Windows 7 桌面版（需自备 WebView2 109） |
| `cloudtrace-desktop-<版本>-win7-x64-full.zip` | Windows 7 桌面版（已附带固定版 WebView2） |

解压后直接运行，**不需要安装**：数据默认放在程序同级的 `data/` 目录，整个目录拷走就是迁移。

### 从源码构建

```bash
git clone https://github.com/skylume/CloudTrace.git
cd CloudTrace
```

```powershell
# 一次产出全部 5 个压缩包（需要 PowerShell 7）
pwsh -File scripts/release.ps1 -Version 1.0.0

# 只出一个
pwsh -File scripts/build.ps1 -Target panel   -Version 1.0.0
pwsh -File scripts/build.ps1 -Target desktop -Version 1.0.0
```

有 `make` 的话更省事（同一套脚本的薄封装，本地与 CI 走的是同一条路径）：

```bash
make build-panel      # 面板版
make build-desktop    # 桌面版
make release          # 全部 5 个包
make dev              # 前端热更新 + 后端 go run
```

产物在 `dist/`。几点说明：

- 前端产物 `web/dist` 随仓库提供；只有改了前端才需要 `make web`（那一步要 Node.js）。
- **Win7 线**需要额外的工具链，`release.ps1` 会自动下载到 `.toolchain/`，与主构建的
  官方 Go 隔离成两个 `GOROOT`，互不污染。
- **Win7 桌面版的 full 包**需要一个固定版本的 WebView2 运行时：设好 `WEBVIEW2_CAB_URL`
  再跑，否则只产出 lite（其余产物不受影响）。
- 桌面版的 exe 没有自定义图标。图标要靠资源编译器嵌进 `.syso`，而那是二进制文件、
  不该进仓库；需要图标时用 wails CLI 构建，或自行生成一次图标资源。

### HTTP 管理面板

两个发行版**共用同一个面板**：桌面版启动时也在本地监听，浏览器打开
`http://127.0.0.1:17443/` 看到的是同一个界面、同一份数据——不是两套实现。

- 开启局域网访问后同网段设备也可访问；监听 `0.0.0.0` 时**强制要求**设置访问 Token。
- 接口：
  - `GET /api/health` — 健康检查与配置告警，**不需要鉴权**，供监控用。
  - `GET|POST /auth/login`、`POST /auth/logout` — 面板登录。
  - `GET /ws` — WebSocket。面板的全部命令与事件都走它，没有一堆 REST 端点。
  - `GET /latest`、`GET /latest.json` — 最新优选结果（纯文本 `ip:port` / 完整 JSON），可直接喂给脚本与 DDNS。
  - `GET /api/download/{id}` — 下载导出物。
  - `GET /api/export/fields` — 导出字段清单。
- 命令行参数（两个版本完全一致）：`-data-dir`、`-port`、`-bind`、`-no-browser`、
  `-log-level`、`-version`。例如 `cloudtrace-panel.exe -bind 0.0.0.0 -port 18080`。

## 📖 使用说明

### 三步拿到最好用的 Cloudflare IP

1. **扫描**：在「扫描」页选一个档位（或直接手调参数），点「开始扫描」。右侧会实时显示进度与筛选漏斗（生成候选 → 延迟达标 → 地区解析 → 最终可用）；要自定义来源就展开「详细设置」。
2. **筛选与测速**：扫描完成后自动进入「结果」页。用地区芯片（在扫描页的过程面板里）或关键词把表筛出来，勾选想要的节点，点「测速选中 N」；测完切到「测速」视图看下载速度与综合评分。
3. **复制与导出**：表格双击复制任意单元格；「导出」对话框支持勾选字段、CSV/JSON/TXT 格式、仅导出合格结果；历史页可随时回看、加载或对比。

### 扫描与来源

- **档位**：内置「快速 / 标准 / 精细」。手调过任意参数后档位显示「已偏离」，点「另存为我的档位」可以把当前这组参数存下来，支持导入导出与设为启动档位。
- **来源**：官方网段、远端地址、自定义文本、本地文件四块可以同时用，来源模式由这四块自动推导，不需要再选一次。
- **加载历史**：之前扫过的话，直接在「历史」页点「加载」，无需重新扫描即可测速。

### 测速

测速必须基于已有的扫描结果（或加载的历史结果）：

- **测速选中**：在结果表里勾选若干节点，点「测速选中 N」。表头的勾选框可以一次选中当前筛出来的全部节点。
- **只测某个地区**：先在扫描页的地区分布芯片里点选地区（结果表会跟着筛），再回到结果页全选并测速。
- **合格阈值**：低于设定速度的节点会被标为不合格，便于快速剔除假高速。

### 结果处理

- **快速复制**：表格中双击任意单元格即可复制该内容；工具栏另有「复制前三名 / 复制全部」。
- **展开详情**：点行首的箭头可以看到该节点的全部字段与 `/cdn-cgi/trace` 明细。
- **导出文件**：支持 `CSV`（可用 Excel 打开，带 BOM）、`JSON`（程序处理）与 `TXT`（每行 `ip:port`，可直接粘贴进代理客户端）。

### ⚙️ 参数配置指南

扫描页只露最常用的几项，其余在「设置 → 扫描 / 测速」里：

| 参数 | 说明 | 调优建议 |
| :--- | :--- | :--- |
| **档位** | 一组参数的快捷方式（快速 / 标准 / 精细） | 不确定就用「标准」；先跑一遍看结果再调 |
| **端口** | 测试连接的目标端口 | 默认 443。若被干扰或封禁，可试 `2053`、`2083` 等同样支持 TLS 的端口 |
| **并发** | 扫描阶段同时测试的连接数 | 默认 200。宽带较慢或路由器性能弱时建议调低到 50–100，超过 300 会明显加重路由器负担 |
| **延迟阈值** | 延迟过滤阈值 | 默认 230 ms。只保留低于此值的 IP；国内一般建议 200 以内，只要极低延迟可设 150 甚至 100 |
| **采样上限** | 单次扫描生成的 IP 数量上限 | 默认 5000，0 = 不限制。调小更快，调大更全面 |
| **探测模式** | TCPing / HTTPing | TCPing 测 TCP 握手延迟（更快）；HTTPing 测 TTFB（更接近真实访问）。两者数据不可互相比较 |
| **探测次数** | 每个 IP 的延迟探测次数 | 默认 4；0 = 自动（IPv4 三次 / IPv6 两次）。多次探测并发取最小值 |
| **探测超时** | 单次探测等多久算失败 | 默认 1000 ms。弱网可适当放宽 |
| **失败重试** | 探测失败后重试几次 | 默认 0（不重试） |
| **两阶段扫描** | 先用低采样粗筛、再对达标节点精测 | 默认开，开着更快 |
| **采集节点明细** | 是否解析每个节点的地区与运营商 | 默认开。关掉会少发大量请求、明显更快，代价是结果里没有地区与运营商 |
| **来源** | 官方网段 / 远端地址 / 自定义文本 / 本地文件 | 四块可叠加。远端地址每行一个 `URL`，可加备注、可单独启停 |
| **地区白名单 / 黑名单** | 按 IATA 地区码保留或剔除 | 设置页。留空 = 不限 |
| **端口过滤** | 扫描前按端口剔除候选 | 设置页。留空 = 不过滤；填 `443,8443` 表示只保留这两个端口的节点参与测试 |
| **测速地址** | 下载测速的 URL | 默认「自动选择」：先探测出口 ISP，识别到中国移动时自动切换移动友好测速源；也可直接选官方源 / 移动友好 / 移动专属，或手填（带 `http://` 则不走 TLS） |
| **测速并发** | 同时进行的下载测速线程数 | 默认 1（串行最准），最大 16。调到 2~3 可明显提速，但并发过高会互相抢带宽、让读数偏低，也更容易触发 Cloudflare 限速 |
| **合格阈值** | 低于该速度视为不合格 | 默认 0（不筛）。用于剔除假高速节点 |
| **提前收敛** | 收够 N 个合格结果就停止测速 | 默认 10（范围 1–100）。只想要几个可用节点时设小，显著缩短测速时间 |
| **测速间隔** | 每个 IP 之间的等待时间 | 默认 1.2 s。间隔过小容易触发 Cloudflare 限速 |
| **单次下载时长** | 每个节点测多久 | 默认 10 s。调短更快但读数抖动更大 |
| **最大下载量** | 单次测速最多下载多少 MB | 默认 0（不限）。手机热点、按流量计费的宽带上值得设一个上限 |
| **熔断阈值** | 连续几次 429 就停止本批测速 | 默认 3（范围 1–100）。调大能让测速多扛一会儿，但被限速之后测出来的速度已经不可信 |
| **关闭窗口时收进托盘** | 关闭窗口后继续在后台跑 | 默认开启（桌面版）。扫描要跑几分钟，关窗口多半是想让它去后台；真要退出请用托盘菜单里的「退出」 |

> ⚠️ **注意**：改完端口、并发、阈值等参数后需**重新扫描**，新参数才会在扫描阶段生效。参数之间配合不当（比如并发拉满而超时只有 1 秒、或者阈值比采样数还苛刻）时，扫描页与设置页都会给出提示——**只是提示，不会替你改**。

## ⚠️ 常见问题

### 1. 杀毒软件报毒怎么办？

程序是**单个静态链接的可执行文件**：没有自解压、不释放临时文件、不写注册表（除非
你自己打开开机自启）。这类产物被误报的概率远低于「把解释器打包进去再自解压」的做法。

仍然被误报时，请添加信任；不放心的话可以下载源码自行构建——构建过程不依赖任何
预编译的二进制，`scripts/` 下的脚本就是 CI 用的那一套。

### 2. Windows 7 兼容说明

Win7 需要单独一条构建线：现代 Go 工具链产出的二进制默认跑不起来，因此发布包里
Win7 的两个产物由社区维护的分支工具链编译。

桌面版还额外需要 WebView2 运行时，而**系统自动安装的那个版本在 Win7 上装不上**，
所以 Win7 桌面版分两种包：`lite` 需要你自备 WebView2 109，`full` 已经把那个固定
版本附在包里。面板版没有这个依赖，Win7 上只有面板版是零前提的。

### 3. 局域网访问提示要 Token

绑定 `0.0.0.0` 之后面板对同网段可见，因此**强制要求**设置访问 Token。只绑回环地址
（默认）时本机访问免鉴权，脚本直接读 `/latest` 即可。

## 🧪 验证测试

```bash
# 后端：单元测试 + 竞态检测 + 覆盖率
go test ./... -race -count=1 -timeout 600s

# 前端：类型检查 + 单元测试
cd web && npm ci && npm run typecheck && npm test
```

CI（`.github/workflows/ci.yml`）在每个 PR 上跑同一套，另加 `gofmt`、`go vet` 与
两个构建标签的编译检查——两个发行版都要能编过。

测试与被测代码放在一起（`internal/<包>/<文件>_test.go`、`web/src/**/*.spec.ts`）。
几条守得比较紧的：

| 位置 | 覆盖内容 |
| :--- | :--- |
| `internal/scan` | 候选池生成、前置过滤顺序（端口 → 黑名单 → 白名单）、两阶段共用同一个 ctx、`verify_nodes=false` 时**真的零** trace 请求 |
| `internal/speed` | 参数补齐与校验、熔断按**连续**次数计、提前收敛要真的取消在跑的任务、选源缓存 |
| `internal/server` | 命令契约：参数非法同步回错误码、任务互斥、设置补丁与来源标记、档位只读 |
| `internal/config` | 校验边界、补丁形状、参数来源表、档位存储；另有两条守卫：**设置页声明的键必须真的存在**、**每个配置项都得有人读** |
| `internal/history` | 索引与记录的一致性、ID 形状校验、软删除与撤销窗口、同参数去重 |
| `internal/adaptive` | 红线：`user` 来源的值只建议、一个字节都不改 |
| `web/src/**/*.spec.ts` | 参数联动、档位换算、离线守卫（禁止任何远程资源）、对比度实测 |

测试**不访问外网**：网络原语全部注入，单测只用回环地址与 `httptest`。

## 📦 打包发布

```powershell
# 一次产出全部 5 个产物
pwsh -File scripts/release.ps1 -Version 1.0.0

# 或走 make（同一套脚本的薄封装）
make release VERSION=1.0.0
```

| # | 产物 | 说明 |
| :- | :--- | :--- |
| 1 | `cloudtrace-panel-<版本>-win-x64.zip` | 面板版（Win10+） |
| 2 | `cloudtrace-desktop-<版本>-win-x64.zip` | 桌面版（Win10+） |
| 3 | `cloudtrace-panel-<版本>-win7-x64.zip` | 面板版（Win7） |
| 4 | `cloudtrace-desktop-<版本>-win7-x64-lite.zip` | 桌面版（Win7），不含 WebView2 |
| 5 | `cloudtrace-desktop-<版本>-win7-x64-full.zip` | 桌面版（Win7），含固定版 WebView2 |

`lite` 与 `full` 共用同一个 exe，只差是否附带 `webview2/` 目录。

打一个 `v1.2.3` 形式的 tag 会触发 `.github/workflows/release.yml`，在 CI 上产出同一套
并挂到同一个 Release。本地脚本与 CI 走的是同一份代码，不存在「本地能打、CI 打不出来」。

### 只出产物、不发 Release（测试版）

想拿一套测试包但不发正式版，**手动触发同一个 workflow** 即可，不需要另外的脚本：

1. 仓库页 → **Actions** → 左侧选 **Release** → 右上 **Run workflow**
2. 版本号填一个（例如 `0.0.0-test`）。留空会用 `0.0.0-dev`
3. 跑完后在同一页面的 **Artifacts** 区域下载那 5 个包

**不会建 Release**：汇总发布那一步只在打 tag 时执行（条件是 `github.ref` 以
`refs/tags/` 开头），手动触发时它被跳过，前面的构建与打包照常跑完。
