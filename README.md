# ☁️ CloudTrace 云迹

[![Go 1.25+](https://img.shields.io/badge/Go-1.25%2B-00ADD8.svg)](https://go.dev/)
[![License](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

**CloudTrace 云迹** 是一款带有现代化图形界面的 Cloudflare IP 扫描与测速工具，  
同时提供 **桌面版（原生窗口）** 与 **纯 HTTP 管理面板** 两种形态：两者共用同一份
handler 与同一份数据，桌面版开着的时候浏览器也能访问同一个面板。  
融合了 [XIU2/CloudflareSpeedTest](https://github.com/XIU2/CloudflareSpeedTest) 的高效测速逻辑与 [xiaolin-007/CloudFlareScan](https://github.com/xiaolin-007/CloudFlareScan) 的美观 UI 设计理念。

## ✨ 功能特性

### 🚀 智能高效扫描
- **全异步高并发**：Go 协程池实现，并发数由你定（默认 200，可调到上万），极速完成海量 IP 筛选。
- **智能随机采样**：从 Cloudflare 官方 CIDR 段智能拆分 /24 子网并随机生成 IP，自动去重并支持采样上限，避免无意义遍历。
- **双延迟模式**：TCPing（TCP 握手延迟，基准）与 HTTPing（TTFB，阈值自动 ×1.3/×4.0 换算），应对不同网络干扰环境。
- **精准 TCP 延迟**：多次探测并发发起取最小值，数据更真实可靠。
- **一个框吃所有格式**：自定义来源只需把内容粘进一个输入框 —— CIDR、单个 IP、`IP:端口`、IP 段（`a-b`）、域名、带 `http(s)://` 前缀的链接、`#` 注释全部自动识别；输入时实时显示「网段 / 指定节点 / 段 / 域名」解析预览。
- **远程数据源**：可配置多个远程节点列表 URL（各自独立启停 + 重试次数/间隔/超时），扫描开始时自动拉取并与自定义来源合并，支持 JSON 与 `IP:端口` 文本的自适应解析；也可先「拉取预览」再决定是否扫描。
- **端口前置过滤**：在 TCP 测试之前先按端口剔除候选，省下并发预算（对齐参考项目的「先过滤再测试」顺序）。

### ⚡ 专业下载测速
- **内置真实测速**：通过 `speed.cloudflare.com` 下载大文件实测带宽（校验状态码、响应头后计时、chunked 解码，杜绝假高速）。
- **自动测速源选择**：`auto` 模式会先探测出口 ISP，识别到中国移动宽带时自动切换移动友好测速源，避免测出的「最快 IP」被绕路/限速误导。
- **限速熔断与并发控制**：连续命中 HTTP 429 会自动熔断本批测速；支持 1~16 并发与「提前收敛」（收够 N 个合格结果即停止）。
- **综合评分排名**：`score = 速度权重 × MB/s ÷ (1 + 延迟权重 × 延迟秒)`，权重可在设置中调整，比单一速度更科学。
- **可用性验证**：测速前校验节点 `Server: cloudflare`，自动淘汰被劫持 / 非 CF 节点。
- **单点 / 地区 / 完全测速**：表格勾选单点直测、地区芯片多选批量测速、或全量测速。
- **测速地址预设 + 自定义**：内置「自动选择 / Cloudflare 官方 / 移动友好 / 移动专属」四个预设一键切换，也可选「自定义…」手填任意 URL（`http://` / `https://` 决定是否走 TLS）。
- **分地区 TopN**：完全测速时可按 IATA 地区分桶，每个地区只保留延迟最低的 N 个再测速（地区测速不受影响，用户选了哪几个地区就全测）。

### 🎯 精准节点识别
- **双栈全面覆盖**：全面支持 Cloudflare 官方 IPv4 与 IPv6 地址段扫描。
- **IATA 深度解析**：自动获取节点的 IATA 机场代码，并内置 80+ Cloudflare 常见代码的中文汉化映射（如 NRT->东京, HKG->香港）。
- **双重识别机制**：优先解析 `/cdn-cgi/trace`，若失败自动回退解析 HTTP 响应头中的 `CF-RAY` 字段，确保识别成功率。

### 🎨 现代化交互体验
- **五页信息架构**：左侧导航「扫描 → 结果 → 测速 → 历史 → 设置」，顶部状态胶囊 + 全局进度条 + 随页面变化的主操作按钮。
- **指标卡**：结果页/测速页顶部各有 4 张统计卡（可用 IP、覆盖地区、最低/平均延迟；最快/平均下载、合格节点、结果总数），筛选时实时联动。
- **结果页**：漏斗统计（生成 → 延迟达标 → 地区解析 → 可用）、地区计数芯片点选过滤（支持全选/清空）、IP 表格与延迟阈值筛选（支持勾选全部/清空）。
- **测速表格**：红黄绿颜色预警（延迟/速度）、前三名金银铜高亮、综合评分列；双击单元格快速复制。
- **全自定义弹窗**：统一风格的消息框（宽度自适应，长文本不裁切）、确认弹窗与导出对话框（可勾选导出字段、CSV/JSON/TXT 格式、仅导出合格结果）。
- **轻提示**：操作反馈以右下角 Toast 呈现，不再打断操作流程。
- **空状态引导**：无数据时显示图标 + 文案 + 快捷入口，而不是一张空白表格。
- **系统托盘**：关闭窗口默认收进托盘（可关掉），托盘图标悬停显示任务进度，菜单可显示主窗口、停止当前任务、退出。

### 🌐 双形态发行
- **桌面版**：原生窗口，同时在本机监听（默认 `127.0.0.1:17443`），浏览器打开就是同一个面板——不是两套实现，是同一个 handler 的两个出口。
- **面板版**：纯 HTTP 服务（不带 GUI 依赖，体积更小），一个 exe 启动，浏览器管理扫描/测速/历史/设置。
- **WebSocket 实时推送**：进度、日志、结果一路推过来；支持 Token 鉴权与局域网访问开关。
- **双 UI 同步**：桌面窗口与浏览器面板共享同一任务状态，可同时打开、互相实时可见。

### 💾 完善的数据管理
- **自动历史存档**：扫描与测速结果自动带时间戳保存，并实时更新 `latest` 副本，支持一键加载历史记录，无需重复扫描。
- **智能空间清理**：自动清理旧版命名格式文件，自动保留最新 5 份历史记录，避免磁盘空间无序浪费。
- **多格式导出**：支持将结果一键导出为 CSV / JSON / TXT 三种格式；TXT 每行输出 `ip:port`，可直接粘贴进代理客户端。
- **原子写入**：设置与历史文件均采用「临时文件 + fsync + 原子替换」写入，进程中途崩溃也不会留下半截 JSON。
- **单实例保护**：同一时间只允许运行一个实例，避免桌面版与面板版抢占端口与历史目录（`CLOUDTRACE_ALLOW_MULTI=1` 可强制多开）。

### ⚒️ 极致系统兼容
- **Win7 深度适配**：单独一条构建线（社区维护的 Go 分支工具链），并为 Win7 桌面版附带固定版本的 WebView2 运行时——系统自带的那个版本在 Win7 上装不上。

## 🚄 安装与运行

### 环境要求

- **运行**：Windows 7 SP1 及以上。
- **从源码构建**：Go 1.25+；只在需要重新构建前端时才要 Node.js 18+。
  桌面版**不需要** wails CLI，也**不需要** C 编译器——直接 `go build` 即可。

### 使用预编译版本

从 [Releases](https://github.com/skylume/CloudTrace/releases/latest) 页面下载对应压缩包：

| 包 | 适用 |
| :--- | :--- |
| `cloudtrace-panel-<版本>-win-x64.zip` | Windows 10/11 面板版：双击后浏览器访问 |
| `cloudtrace-desktop-<版本>-win-x64.zip` | Windows 10/11 桌面版：原生窗口 |
| `cloudtrace-panel-<版本>-win7-x64.zip` | Windows 7 面板版 |
| `cloudtrace-desktop-<版本>-win7-x64-lite.zip` | Windows 7 桌面版（需自备 WebView2 109） |
| `cloudtrace-desktop-<版本>-win7-x64-full.zip` | Windows 7 桌面版（已附带固定版 WebView2） |

解压后直接运行，**不需要安装**：数据默认放在程序同级的 `data/` 目录，整个目录拷走就是迁移。

### 从源码构建

```bash
git clone https://github.com/skylume/CloudTrace.git
cd CloudTrace
```

```powershell
# 一次产出全部 5 个压缩包（需要 PowerShell 7）
pwsh -File scripts/release.ps1 -Version 1.0.0

# 只出一个
pwsh -File scripts/build.ps1 -Target panel   -Version 1.0.0
pwsh -File scripts/build.ps1 -Target desktop -Version 1.0.0
```

有 `make` 的话更省事（同一套脚本的薄封装，本地与 CI 走的是同一条路径）：

```bash
make build-panel      # 面板版
make build-desktop    # 桌面版
make release          # 全部 5 个包
```

产物在 `dist/`。几点说明：

- 前端产物 `web/dist` 随仓库提供；只有改了前端才需要 `make web`（那一步要 Node.js）。
- **Win7 线**需要额外的工具链，`release.ps1` 会自动下载到 `.toolchain/`，与主构建的
  官方 Go 隔离成两个 `GOROOT`，互不污染。
- **Win7 桌面版的 full 包**需要一个固定版本的 WebView2 运行时：设好 `WEBVIEW2_CAB_URL`
  再跑，否则只产出 lite（其余产物不受影响）。
- 桌面版的 exe 没有自定义图标。图标要靠资源编译器嵌进 `.syso`，而那是二进制文件、
  不该进仓库；需要图标时用 wails CLI 构建，或自行生成一次图标资源。

### HTTP 管理面板

两个发行版**共用同一个面板**：桌面版启动时也在本地监听，浏览器打开
`http://127.0.0.1:17443/` 看到的是同一个界面、同一份数据——不是两套实现。

- 开启局域网访问后同网段设备也可访问；监听 `0.0.0.0` 时**强制要求**设置访问 Token。
- 接口：
  - `GET /api/health` — 健康检查与配置告警，**不需要鉴权**，供监控用。
  - `GET|POST /auth/login`、`POST /auth/logout` — 面板登录。
  - `GET /ws` — WebSocket。面板的全部命令与事件都走它，没有一堆 REST 端点。
  - `GET /api/latest`、`GET /api/latest.json` — 最新结果（纯文本 / JSON）。
  - `GET /api/download/{id}` — 下载导出物。
  - `GET /api/export/fields` — 导出字段清单。
- 命令行参数（两个版本完全一致）：`-data-dir`、`-port`、`-bind`、`-no-browser`、
  `-log-level`、`-version`。例如 `cloudtrace-panel.exe -bind 0.0.0.0 -port 18080`。

## 📖 使用说明

### 只需简单三步即可找到最快的 Cloudflare IP：

1. **扫描**：在「扫描」页选择 IP 版本与参数，点击「开始扫描」；漏斗实时显示 生成 → 延迟达标 → 地区解析 → 可用。若不用官方段，把 CIDR / IP / `IP:端口` / IP 段 / 域名 粘进「来源」框即可（输入时下方会实时显示解析预览）；也可开启「数据源」从远程列表拉取。
2. **筛选与测速**：扫描完成后自动进入「结果」页，点选地区芯片过滤，勾选 IP 单点测速、按所选地区测速，或切到「测速」页完全测速（支持测速阈值筛选与综合评分排名）。
3. **复制与导出**：表格双击复制任意单元格；「导出」对话框支持勾选字段、CSV/JSON/TXT 格式、仅导出合格结果；历史页可随时回看与重新加载。

---

### 📋 核心操作详解

#### 1. 扫描与加载
- **首次扫描**：选择 IPv4 或 IPv6 开始扫描。程序会并发测试海量 IP 的延迟，并自动剔除超时及高延迟的 IP。
- **加载历史**：如果之前已经扫描过，可以直接点击「加载 IPv4/IPv6 扫描结果」，无需重新扫描即可直接进行测速。

#### 2. 测速模式
测速必须基于已有的扫描结果（或加载的历史结果）：
- **地区测速**：在「地区码」输入框填写 3 位 IATA 代码（如 `HKG`、`NRT`、`LAX`），程序会筛选出属于该地区的 IP 进行下载测速。
  > 💡 **提示**：可在扫描状态和统计信息中查看当前可用的地区码列表。输入地区码时会自动转为大写。
- **完全测速**：不填地区码，直接点击「完全测速」。程序会自动选取延迟最低的前 N 个 IP（N 由「数量」参数决定）进行下载测速。

#### 3. 结果处理
- **快速复制**：在测速结果表格中，**双击任意单元格**（如 IP 地址、地区、延迟等），即可将该内容快速复制到剪贴板，方便直接粘贴到其他工具中使用。
- **导出文件**：点击「导出结果」，可将扫描和测速结果分别导出。支持 `CSV`（可用 Excel 打开，带 BOM）、`JSON`（程序处理）与 `TXT`（每行 `ip:port`，可直接粘贴进代理客户端）。

### ⚙️ 参数配置指南

在主界面的参数面板中，您可以根据自己的网络情况调整以下参数：

| 参数 | 说明 | 调优建议 |
| :--- | :--- | :--- |
| **端口** | 测试连接的目标端口 | 默认 443。如果 443 端口被干扰或封禁，可尝试切换为 `2053`、`2083` 等其他支持 TLS 的端口。 |
| **并发** | 扫描阶段同时测试的连接数 | 默认 200。根据自己的网络环境调整，宽带较慢或路由器性能较弱时，建议调低至 50-100 以防断网 |
| **阈值ms** | 延迟过滤阈值 | 默认 230。只保留延迟低于此数值的 IP。国内一般建议 200 以内，若只要极低延迟节点可设为 150 甚至 100。 |
| **采样上限** | 单次扫描生成的 IP 数量上限 | 默认 5000。全量官方段去重后按此值随机截断；调大更全面但更耗时。 |
| **扫描方式** | TCPing / HTTPing | TCPing 测 TCP 握手延迟（基准）；HTTPing 测 TTFB，数值更高属正常，阈值自动按 ×1.3/×4.0 换算。两者数据不可互相比较。 |
| **探测次数** | 每个 IP 的延迟探测次数 | 0 = 自动（IPv4 三次 / IPv6 两次）。多次探测并发取最小值。 |
| **来源模式** | IP 地址段来源 | 「仅官方」用 Cloudflare 官方 CIDR；「仅自定义」只用输入框内容；「官方+自定义」两者合并。输入框支持 CIDR / 单个 IP / `IP:端口` / IP 段 / 域名 / `http(s)://` 链接 / `#` 注释。（旧配置里的「非标列表」会自动迁移为「仅自定义」） |
| **端口过滤** | 扫描前按端口剔除候选 | 留空 = 不过滤。填 `443,8443` 表示只保留这两个端口的节点参与测试，避免把并发花在注定被淘汰的端口上。 |
| **数据源** | 远程节点列表 | 每行一个 `名称 \| URL`，行首加 `#` 可临时禁用。开启后扫描开始时先拉取列表再与自定义来源合并；可调重试次数/间隔/超时，点「拉取预览」可先看拉到了多少条。 |
| **数量** | 参与下载测速的 IP 数量 | 默认 10。测速较耗时，数量过多等待时间较长。 |
| **测速地址** | 下载测速的 URL | 默认「自动选择」：先探测出口 ISP，识别到中国移动时自动切换到移动友好测速源；也可直接选「Cloudflare 官方 / 移动友好 / 移动专属」，或选「自定义…」手填（带 `http://` 则不走 TLS）。 |
| **测速并发** | 同时进行的下载测速线程数 | 默认 1（串行最准）。调到 2~3 可明显提速，但并发过高会互相抢带宽、让读数偏低，也更容易触发 Cloudflare 限速。 |
| **提前收敛** | 收够 N 个合格结果就停止测速 | 默认 0（不提前停止）。只想要几个可用节点时可设为 3~10，显著缩短测速时间。 |
| **分地区 TopN** | 完全测速时每个地区保留几个 | 默认 0（不限）。设为 1~3 时，完全测速会先按 IATA 地区分桶、每桶取延迟最低的 N 个再下载测速，避免单个地区刷屏。地区测速不受此项影响。 |
| **地区码** | Cloudflare 节点 3 位 IATA 代码 | 在「测速」页填写，或直接在「结果」页点选地区芯片（支持多选）。常见：`HKG`、`TPE`、`NRT`、`SIN`、`LAX` |
| **关闭窗口时收进托盘** | 关闭窗口后继续在后台跑 | 默认开启（桌面版设置项）。扫描要跑几分钟，关窗口多半是想让它去后台，而不是把跑到一半的任务掐掉；真要退出请用托盘菜单里的「退出」。 |

> ⚠️ **注意**：修改端口、并发、阈值等参数后，需**重新进行扫描**，新参数才会在扫描阶段生效。

## ⚠️ 常见问题

### 1. 杀毒软件报毒怎么办？

程序是**单个静态链接的可执行文件**：没有自解压、不释放临时文件、不写注册表（除非
你自己打开开机自启）。这类产物被误报的概率远低于「把解释器打包进去再自解压」的做法。

仍然被误报时，请添加信任；不放心的话可以下载源码自行构建——构建过程不依赖任何
预编译的二进制，`scripts/` 下的脚本就是 CI 用的那一套。

### 2. Windows 7 兼容说明

Win7 需要单独一条构建线：现代 Go 工具链产出的二进制默认跑不起来，因此发布包里
Win7 的两个产物由社区维护的分支工具链编译。

桌面版还额外需要 WebView2 运行时，而**系统自动安装的那个版本在 Win7 上装不上**，
所以 Win7 桌面版分两种包：`lite` 需要你自备 WebView2 109，`full` 已经把那个固定
版本附在包里。面板版没有这个依赖，Win7 上只有面板版是零前提的。

## 📂 目录结构

```text
CloudTrace/
├── cmd/
│   ├── panel/            # 面板版入口：纯 Go，浏览器访问
│   └── desktop/          # 桌面版入口：原生窗口（构建标签 desktop）
├── internal/
│   ├── launch/           # 两个入口共用的启动装配
│   ├── platform/         # 平台能力：单实例、开机自启、浏览器、窗口状态、DPI
│   ├── app/              # 依赖容器与生命周期
│   ├── config/           # 配置：加载、校验、补丁、档位、参数来源表
│   ├── model/            # 共享数据模型
│   ├── probe/            # 探测内核：TCP/HTTP 延迟、TLS 校验
│   ├── scan/             # 扫描任务：候选池、前置过滤、两阶段
│   ├── speed/            # 测速任务与测速源选择
│   ├── score/            # 综合评分
│   ├── adaptive/         # 自适应判定（绝不覆盖用户的显式选择）
│   ├── geo/              # ASN 库与归属地
│   ├── history/          # 历史：索引、参数快照、对比、软删除
│   ├── exporter/         # CSV / JSON / TXT 导出
│   ├── health/           # 配置体检
│   ├── server/           # HTTP + WebSocket：静态资源、REST、命令分发
│   ├── event/            # 事件总线
│   ├── task/             # 任务编排（状态机 + 进度节流）
│   └── atomicfile/       # 原子写文件
├── web/                  # 前端（Vue 3 + Vite + TS）；产物 web/dist 由 go:embed 打进二进制
├── assets/               # 内置的官方网段数据
├── scripts/              # 构建与打包脚本（本地与 CI 共用同一套）
├── .github/workflows/    # CI 与发布流水线
└── Makefile              # 构建入口（scripts/ 的薄封装）
```

## 🧪 验证测试

```bash
# 后端：单元测试 + 竞态检测 + 覆盖率
go test ./... -race -count=1 -timeout 600s

# 前端：类型检查 + 单元测试
cd web && npm ci && npm run typecheck && npm test
```

CI（`.github/workflows/ci.yml`）在每个 PR 上跑同一套，另加 `gofmt`、`go vet` 与
两个构建标签的编译检查——两个发行版都要能编过。

测试与被测代码放在一起（`internal/<包>/<文件>_test.go`、`web/src/**/*.spec.ts`）。
几条守得比较紧的：

| 位置 | 覆盖内容 |
| :--- | :--- |
| `internal/scan` | 候选池生成、前置过滤顺序（端口 → 黑名单 → 白名单）、两阶段共用同一个 ctx、`verify_nodes=false` 时**真的零** trace 请求 |
| `internal/speed` | 参数补齐与校验、熔断按**连续**次数计、提前收敛要真的取消在跑的任务、选源缓存 |
| `internal/server` | 命令契约：参数非法同步回错误码、任务互斥、设置补丁与来源标记、档位只读 |
| `internal/config` | 校验边界、补丁形状、参数来源表、档位存储；另有两条守卫：**设置页声明的键必须真的存在**、**每个配置项都得有人读** |
| `internal/adaptive` | 红线：`user` 来源的值只建议、一个字节都不改 |
| `web/src/**/*.spec.ts` | 参数联动、档位换算、离线守卫（禁止任何远程资源）、对比度实测 |

测试**不访问外网**：网络原语全部注入，单测只用回环地址与 `httptest`。

## 📦 打包发布

```powershell
# 一次产出全部 5 个产物
pwsh -File scripts/release.ps1 -Version 1.0.0

# 或走 make（同一套脚本的薄封装）
make release VERSION=1.0.0
```

| # | 产物 | 说明 |
| :- | :--- | :--- |
| 1 | `cloudtrace-panel-<版本>-win-x64.zip` | 面板版（Win10+） |
| 2 | `cloudtrace-desktop-<版本>-win-x64.zip` | 桌面版（Win10+） |
| 3 | `cloudtrace-panel-<版本>-win7-x64.zip` | 面板版（Win7） |
| 4 | `cloudtrace-desktop-<版本>-win7-x64-lite.zip` | 桌面版（Win7），不含 WebView2 |
| 5 | `cloudtrace-desktop-<版本>-win7-x64-full.zip` | 桌面版（Win7），含固定版 WebView2 |

`lite` 与 `full` 共用同一个 exe，只差是否附带 `webview2/` 目录。

打一个 `v1.2.3` 形式的 tag 会触发 `.github/workflows/release.yml`，在 CI 上产出同一套
并挂到同一个 Release。本地脚本与 CI 走的是同一份代码，不存在「本地能打、CI 打不出来」。

### 只出产物、不发 Release（测试版）

想拿一套测试包但不发正式版，**手动触发同一个 workflow** 即可，不需要另外的脚本：

1. 仓库页 → **Actions** → 左侧选 **Release** → 右上 **Run workflow**
2. 版本号填一个（例如 `0.0.0-test`）。留空会用 `0.0.0-dev`
3. 跑完后在同一页面的 **Artifacts** 区域下载那 5 个包

**不会建 Release**：汇总发布那一步只在打 tag 时执行（条件是 `github.ref` 以
`refs/tags/` 开头），手动触发时它被跳过，前面的构建与打包照常跑完。

产物：
- 桌面版 `dist/CloudTrace-<版本>/`（或单 exe），双击即用，设置中可开 HTTP 面板
- 面板版 `dist/CloudTrace-Panel-<版本>/`（或单 exe），终端运行后浏览器访问打印的地址
